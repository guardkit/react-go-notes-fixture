**priority_rationale**: The request has two clauses and the ordering follows them. FEAT-PO-001 goes first because nothing can be shown until the done flag reaches the list's row data — it is the single root dependency and the cheapest to settle. FEAT-PO-002 follows as the literal 'show each note's done flag' deliverable; on its own it already satisfies the minimum ask, which makes it the natural first shippable increment. FEAT-PO-003 then delivers the second clause, 'clearly marked as done', which is a refinement of an indicator that must already exist. FEAT-PO-004 and FEAT-PO-005 are ordered last because they harden an already-working feature rather than create it, but they are not optional extras: the word 'clearly' in the request is a quality bar that a colour-only implementation would fail, so they belong in the same roadmap. FEAT-PO-004 and FEAT-PO-005 can proceed in parallel with FEAT-PO-003's visual polish once FEAT-PO-002 lands. Ordering is advisory reasoning, not a scored ranking.
