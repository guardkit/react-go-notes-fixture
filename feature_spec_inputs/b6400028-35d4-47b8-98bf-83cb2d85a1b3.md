# Feature Spec Input: b6400028-35d4-47b8-98bf-83cb2d85a1b3

**Originator**: U03QR8WKT29

**Request**: Starting the app sometimes fails while setting up Keycloak: Keycloak reports itself healthy a little before its admin login is ready, so the first admin login in the realm setup (scripts/keycloak/configure-realm.inside.sh, run by scripts/keycloak-config.sh for the checks, the local stack and every deploy) gets 503 Service Unavailable, or a refused connection, and the whole start-up stops. Make the realm setup wait for Keycloak to be ready: retry the admin login and the first admin call only on 503 or a refused connection, give up after at most 2 minutes in total with a clear message saying Keycloak was not ready in time, fail straight away on any other error such as a wrong password, and never show the admin password on a command line or in any message. Add tests showing that the setup succeeds when Keycloak answers 503 a few times before it is ready, fails within the time limit when Keycloak never becomes ready, and fails at once on a wrong password.

**priority_rationale**: The retry loop (FEAT-PO-001) is first because it is the behaviour the failing start-up actually needs, and everything else either refines it or proves it. Credential-safe transport (FEAT-PO-004) is ordered before it in dependency terms rather than after: the retry loop re-issues the login, so retrofitting secret hygiene afterwards would mean rewriting every call site the loop introduces, and the request states the password constraint unconditionally. The 2-minute budget and its timeout message (FEAT-PO-002) and the fail-fast taxonomy (FEAT-PO-003) are the two halves of the loop's exit policy and can be developed in parallel once the loop exists; the budget is listed first because without it a retry loop is an unbounded hang, which is a worse failure mode than a slow failure. Tests come last as a group because they assert on implemented behaviour, but FEAT-PO-005 through FEAT-PO-007 can be written against the stand-in Keycloak as soon as the corresponding behaviour lands, so they need not serialise behind the whole epic. Nothing here is scored or ranked numerically; this ordering is advisory reasoning for a human to adjust.
