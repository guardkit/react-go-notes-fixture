## Acceptance Criteria

- The contract's note object schema declares `done` as a required boolean property (ASSUM-001), so a note object in the `GET /api/notes` response satisfies the contract's required boolean `done` field.
- A note object that omits the `done` flag fails the contract check for the notes listing (the existing `TestContractRefusesForbiddenResponses` in `apps/api/internal/notes/contract_test.go` gains a "missing done" case alongside its "missing createdAt" case at line 105).

- Contract validation fails when the live response drifts from the contract: a `GET /api/notes` response without the `done` flag is refused by the contract router built from `contract/openapi.yaml`.
- The contract remains valid OpenAPI (`doc.Validate` in `contractRouter`, `apps/api/internal/notes/contract_test.go:30` passes) and no existing note field (`id`, `label`, `createdAt`) is renamed or removed — the change is additive only.
- `npm run contract:check` (regenerate and fail on drift) passes once the web types are regenerated by TASK-4C9B-003.
