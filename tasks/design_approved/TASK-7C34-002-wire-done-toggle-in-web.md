Let the signed-in user set a note's done flag from the web client by calling `PATCH /api/notes/{id}`, updating the in-memory list from the returned note (no follow-up GET), and surfacing a 404 as the note having gone away.

## The words of the request this task serves

List lines: 1, 2, 3, 4, 5

"Add PATCH /api/notes/{id} so the signed-in owner can set a note's done flag to true or false; it returns the updated note, and answers 404 for a note that does not exist or belongs to someone else"

## Acceptance Criteria

- `api.ts` gains a client method that sends `PATCH /api/notes/{id}` with the bearer token, mirroring the `listNotes`/`createNote` call style at `apps/web/src/api.test.ts:55` (bearer header, base-relative URL), and returns the updated `Note` parsed from the 200 response body.
- The 200 handler updates the in-memory note from the returned note without a follow-up GET: after toggling, the list shows the new `done` value and the other fields unchanged, and the test asserts only one PATCH request was issued (no second GET/list call).
- `App.tsx` renders a control per note that toggles its `done` flag and re-renders the row from the PATCH response; the toggle is a labelled `button` (not an anonymous link) so it is reachable by role.
- A 404 is handled distinctly: the client does not crash and the UI reports the note is gone/lost (matching how a refused token is reported via `role="alert"` in `apps/web/src/App.tsx:79`), rather than silently leaving a stale `done` value.
- Regenerate/refresh `apps/web/src/api-types.ts` so the PATCH operation's request and response types come from `contract/openapi.yaml`, and the client method is typed against them.
- All modified files pass the project-configured lint/format checks with zero errors (repo's own `scripts/check.sh`; no separate lint task).

## Implementation Notes

- `api-types.ts` is generated by `tools/contract/generate.mjs` from `contract/openapi.yaml` — regenerate rather than hand-editing it, and let the client method signature follow the generated types (this task runs after TASK-7C34-001 which owns the OpenAPI/`api-types.ts` contract).
- Do not name a web address the request did not name — reuse the existing same-origin `/api/notes/{id}` base; tokens stay in memory (see the reload note at `tests/e2e/specs/journey.spec.ts:155`).
- Follow the existing fetch/`Response.json` test-mock pattern already used in `apps/web/src/api.test.ts` when writing the new tests in `patch.test.ts`.
